# 桌宠皮肤包格式（pet.json）—— 规范 v1

> 阶段 3 产出。本规范定义桌宠皮肤包的**描述文件格式与合并规则**，
> 是阶段 8「样式商城」导入/导出的校验依据，也是「两代兼容」
> （新增 sprite 序列帧、保留现有 SVG 猫）的落地形式。

---

## 1. 设计目标与约束

| 目标 | 说明 |
| --- | --- |
| **默认值等于现状** | 不提供任何皮肤时，行为与当前内置 SVG 猫完全一致；皮肤只做「覆盖」 |
| **缺字段可降级** | 缺失或非法的字段回落到内置默认，而不是白屏或抛错（阶段 3 检测项） |
| **两代兼容** | `render.kind` 为 `svg`（现役）或 `sprite`（新增序列帧），同一套状态表驱动 |
| **不引入网络** | 第一期只做本地包；在线索引仅预留接口，渲染进程不拿网络权限 |

---

## 2. 文件位置

```
renderer/pet/skins/<内置皮肤 id>/pet.json      # 随应用分发的内置皮肤
<userData>/pets/<皮肤 id>/pet.json              # 用户导入的皮肤（阶段 8）
```

- 皮肤 id 必须匹配 `^[a-z0-9][a-z0-9-]{0,47}$`（与能力 id 同风格，避免路径穿越）。
- 资源（图片/音频）与 `pet.json` 同目录，用**相对路径**引用；
  禁止 `..`、绝对路径、`file://` 等（阶段 8 在校验层拒绝）。

---

## 3. 顶层结构

```jsonc
{
  "format": "pet",          // 必填，固定 "pet"，用于识别文件类型
  "version": 1,             // 必填，本规范版本
  "id": "builtin-cat",      // 必填，见上节命名规则
  "name": "内置小猫",        // 必填，展示名
  "author": "",             // 可选
  "render": { ... },        // 必填，见 §4
  "clips": { ... },         // 可选，见 §5
  "sounds": { ... }         // 可选，见 §6
}
```

未列出的字段一律忽略（前向兼容：新版本加的字段不会让旧版本报错）。

---

## 4. `render`：这一代怎么画

```jsonc
{
  "kind": "svg",            // 必填，"svg" | "sprite"
  "size": { "width": 90, "height": 90 },   // 可选，宠物视觉框的**设计**尺寸
  "svg": {
    "file": "cat.svg",      // kind=svg 时必填
    "colorMap": {           // 可选：按 CSS 变量换色（见 §7）
      "--cat-fur": "#f5a623",
      "--cat-ear": "#f8c774"
    }
  },
  "atlas": {                // kind=sprite 时必填
    "file": "atlas.png",
    "frameWidth": 64,
    "frameHeight": 64
  }
}
```

**校验规则**

| 情况 | 处理 |
| --- | --- |
| `kind` 缺失或非法 | 回落到 `svg`（现役实现），并记录一条 warning |
| `kind: "svg"` 但缺 `svg.file` | 回落到**内置** SVG 猫（不使用该皮肤的图形） |
| `kind: "sprite"` 但缺 `atlas` 或帧宽高非正 | 回落到 `svg` 分支；若无 `svg` 则用内置 SVG 猫 |
| `size` 缺失 | 用内置设计尺寸（90×90） |

> 视觉框的**实际**尺寸不由 `size` 决定：吸附用的是运行时 `getBBox()` 实测值
> （见 `renderer/pet/anchor.js`）。`size` 只是设计标注，用于皮肤预览与资源核对。

---

## 5. `clips`：动作覆盖

键名即**状态名**，必须是内置状态表里的合法状态
（`idle` / `sleep` / `walk` / `celebrate` / `interact` / `snap` / `drag`，见
`renderer/pet/behavior.js` 的 `PET_BEHAVIOR.STATES`）。
未知状态名**忽略**并记 warning —— 这样将来新增状态不会让旧皮肤报错。

```jsonc
"clips": {
  "idle":    { "frames": [0, 1, 2, 1], "fps": 6, "loop": true },
  "walk":    { "frames": [3, 4, 5, 4], "fps": 10, "loop": true },
  "interact":{ "frames": [6, 7], "fps": 12, "loop": false, "duration": 600 }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `frames` | 是（sprite） | 帧序号数组，必须是 ≥0 的整数；空数组视为无效并忽略该 clip |
| `fps` | 否 | 播放帧率，默认 8；非正数或非数字用默认 |
| `loop` | 否 | 是否循环。**不覆盖状态表里的 `loop`**：状态表为准，避免皮肤把一次性状态改成循环导致状态机无法回落 |
| `duration` | 否 | 一次性状态的时长；仅当状态本身 `loop: false` 时生效 |

**合并规则**

1. 以内置状态表为基底，逐个状态覆盖 `frames` / `fps`。
2. 未在 `clips` 中出现的状态沿用内置定义。
3. `loop` 与 `duration` 的最终取值**以状态表为准**（皮肤不能破坏状态机语义）。
4. 优先级与可打断关系**不可被皮肤覆盖** —— 它属于状态机契约，不属于皮肤。

---

## 6. `sounds`：可选音效

```jsonc
"sounds": { "interact": "meow.ogg" }
```

键名同样是状态名；文件必须是同目录下的相对路径，扩展名白名单
（阶段 8 校验）：`.ogg` / `.mp3` / `.wav` / `.m4a`。

---

## 7. 换色机制（`colorMap`）

现有 SVG 猫的颜色是直接写在 `<svg>` 元素属性上的（`fill="#f5a623"` 等），
因此换色需要两步：

1. 皮肤的 `colorMap` 给出 `CSS 变量名 → 颜色`；
2. 加载器把变量写到桌宠根元素（`.pet-body`）上，SVG 内部相应位置改用
   `fill="var(--cat-fur)"` 之类引用。

第一阶段只支持「变量名 → 颜色」这种映射，不做任意 CSS 注入
（避免皮肤携带可执行内容）。变量名必须匹配 `^--[a-zA-Z0-9-]+$`。

## 8. 校验结果约定

校验函数（`renderer/pet/skin.js` 的 `validatePetSkin`）返回：

```js
{
  ok: boolean,           // 是否是一个可用的皮肤（format/version/id/name/render 基本合法）
  errors: string[],      // 致命问题：该皮肤不可用
  warnings: string[],    // 可自愈问题：已回落/已忽略，皮肤仍可用
  skin: object|null      // 归一化后的皮肤（补全默认值、剔除非法项）
}
```

**红线**：`ok: false` 的皮肤不得被应用；调用方应回落到内置皮肤并提示用户。
校验层绝不抛错 —— 任何异常都转成 `errors` 与 `ok: false`。

---

## 9. 与状态表的关系（一句话总结）

> **状态机决定「什么时候播什么」，皮肤只决定「这个动作长什么样」。**

优先级、可打断关系、一次性状态的回落语义都在状态表里，皮肤无法改变；
皮肤能做的是为每个状态提供自己的画面（帧序列或 SVG 变体）与配色。
